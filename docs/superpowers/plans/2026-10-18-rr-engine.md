# Ridonculous Race Engine (sub-project 1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A headless, seeded Ridonculous Race engine that plays a whole season (teams of two racing legs on one clock,
with travel, money, tasks, encounters, twists, the Chill Zone and the finale), plus its hundred-season audit.

**Architecture:** `js/rr/`, in its own `gs` like The Challenge (`js/ch/`). A leg is a route of stretches; `clock.js`
moves every team through them in time order, so two teams at the same place at the same minute meet; each stretch
kind has its own resolver (travel, task, board, mat). Every random draw comes from `streamFor(seed, salt)`.

**Tech Stack:** ES modules, no build; vitest + jsdom (`vitest.config.js`; audits under `vitest.audit.config.js`).

**Spec:** `docs/superpowers/specs/2026-10-18-ridonculous-race-design.md` (this plan is its §13 sub-project 1).
Also read `docs/ridonculous-race-identities.md` (identities, task types, blends) and
`docs/ridonculous-race-research.md` (why each rule exists).

**Out of this plan** (their own plans later): dialogue and words (sub-project 3), the run tab and the registry entry
(4), the place library beyond the four starter places (2), and these rarer twists: Switchback, Scramble, Partner
Swap, Superleg/No-Rest Leg, Head-to-Head, Starting Line Task/Hazard; and a team's partners getting separated (§7.2),
which needs the place library's branching paths.

## Global Constraints

- No `Math.random()` anywhere in `js/rr/`: every draw comes from `streamFor(seed, '<salt>')` (`js/dr/rng.js`).
- Stats: only `physical endurance mental social strategic loyalty boldness intuition temperament`.
- Gameplay is proportional (`stat * factor`); thresholds only to pick words.
- Archetype rule: sabotage only if `mayScheme(name)` (`js/ch/state.js`); nice archetypes never.
- Temperament is the SPREAD in pressure task types, the LEVEL only in `hands` and `patience`
  (identities doc).
- Identity nudge: ×1.12 on a good type, ×0.88 on a bad type.
- Every event a scene: `addScene(state, kind, who, data, seenBy)`; nobody knows what they didn't see.
- No real country or city names in place data (World Tour rule).
- Season plays in its own `gs`: `setGs({ bonds:{}, perceivedBonds:{}, relationshipDimensions:{}, popularity:{}, episodeHistory:[] })` at the top.
- Popularity: `gs.popularity[name] = (gs.popularity[name] || 0) + delta` for heroic/villainous/cowardly/selfless moments.
- Commit by path: `git commit -m "..." -- <paths>`; never `git add -A`.
- Format id: `RR_FORMAT = 'ridonculous-race'` in `js/rr/format.js` (moves to the registry in sub-project 4).

## Review Focus

1. A flight batch with fewer seats than teams waiting: the overflow takes the next flight, nobody is dropped (Task 6).
2. A team with $0 at a paid stretch: it walks, begs or borrows; the leg never stalls (Task 7).
3. A vehicle that waits for six when fewer than six teams are left in the leg: it leaves at its `maxWait` or when
   every remaining team is aboard (Task 5).
4. Two teams stepping on the mat in the same minute: placement decided by last leg's order, the same every replay
   (Task 12).
5. The smallest and largest casts (6 and 18 teams): the schedule is valid and the finale always starts with three
   teams (Task 3, Task 14).

  - `raceState(nTeams, seed) -> State` in the helper: `raceCast`, `setPlayers(cast)`, `newState`, `addTeams`. Every

### Task 2: Task types, identities and skill

**Files:**
- Create: `js/rr/types.js`, `js/rr/identities.js`, `js/rr/skill.js`
- Test: `tests/rr-skill.test.js`

**Interfaces:**
- Consumes: `S`, `REL` (Task 1); `getBond` from `js/bonds.js`.
- Produces:
  - `TASK_TYPES`: twelve keys `water heights strength stomach nerve brains search perform people travel hands
    patience`, each `{ level: {stat: weight}, spread: boolean }`, values copied exactly from the identities doc's
    table: spread true for `water heights stomach nerve search people`; `hands` level includes
    `temperament: 0.20`; `patience` level `{ temperament: .5, endurance: .3, mental: .2 }`.
  - `IDENTITIES`: the 54 identities of `docs/ridonculous-race-identities.md`, keyed by kebab id
    (`surfers`, `ice-dancers`, … `college-students`), each
    `{ name, group, good: string[], bad: string[], friction: string[], friends: string[] }`; `adversity-twins`
    also has `mishap: 1.5`. Friction and friends hold identity ids.
  - `identityFactor(team, types: string[]) -> number`: product over `types` of 1.12 (good), 0.88 (bad), 1 (neither);
    a `custom` team reads `IDENTITIES[team.custom.strength]`; no identity → 1.
  - `levelOf(name, types) -> number` (0..10): mean over `types` of `Σ weight × S(name, stat)`.
  - `spreadOf(name, types) -> number`: `0.62 + (10 - S(name,'temperament')) * 0.085` if any type is a spread type,
    else `0.62`.
  - `teamwork(state, teamId) -> number`: `0.9 + 0.02 × getBond(a, b)` clamped to `[0.75, 1.1]`, × `0.92` while
    `state.snapped?.[teamId]` is true.
  - `energyFactor(state, name) -> number`: `0.85 + 0.15 × energy / 100`.
  - `teamLevel(state, teamId, types, who = 'both') -> number`: `'both'` → mean of the two `levelOf` ×
    `identityFactor` × `teamwork` × mean `energyFactor`; a name → that person's `levelOf` × `identityFactor` ×
    their `energyFactor`.

### Task 5: The clock

**Files:**
- Create: `js/rr/clock.js`
- Test: `tests/rr-clock.test.js`

**Interfaces:**
- Produces:
  - `runLeg({ teams: [{ id, t }], stretches: Stretch[], resolve }) -> { log, finish, out }`:
    - `log: [{ id, stretch, from, to }]`, `finish: {[id]: minute}`, `out: string[]`.
    - `resolve(team, stretch, t, api) -> { end } | { hold: deadline } | { end, skip: n } | { out: true, end }`.
  - `api`:
    - `here(stretchId, t) -> [{ id, from, to }]`: intervals at that stretch covering `t`, other teams only;
    - `delay(id, minutes)`: push a team's pending end later (its current interval and its place in the queue);
    - `slot(stretchId, capacity, t, dur) -> start`: the earliest start with a free station;
    - `vehicle(stretchId, { waitFor, maxWait }, id, t) -> { departs: minute|null, group }`;
    - `remaining() -> number`: teams not yet past this stretch index.

**The loop (the algorithm the tests don't fully fix):**
- A queue ordered by `(t, order index)`. Pop the earliest team.
- Past the last stretch: `finish[id] = t`.
- Else call `resolve`:
  - `{ end }` → log `[t, end]`, advance one stretch (plus `skip`), re-queue at `end`;
  - `{ out }` → log, add to `out`, drop the team;
  - `{ hold: deadline }` → re-queue the same stretch at `deadline` with a held flag.
